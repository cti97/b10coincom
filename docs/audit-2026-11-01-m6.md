## 1. Verdict

**M6 is the cleanest milestone this series has reviewed.** It touches no consensus, state or type code; the two HTML pages are rendered by `html/template` from an embedded filesystem under a `default-src 'none'` content security policy with no script, no external resource, no `template.HTML`, and those properties are pinned by tests that parse the source; the faucet page is a pure read that cannot solve, sign or submit; `/history` is bounded server-side to 500 blocks and 200 entries regardless of what the client asks; and `send` and `claim --key` go through exactly the print, ceiling, dry-run, confirm, sign path the staking verbs earned in the previous round, with the printed bytes provably the signed bytes. No private key byte is printed, logged or written on any `--key` path. No Critical or High finding.

**One Medium.** The `/history` scan, and the explorer that shares it, cannot be cancelled and has no concurrency bound. A handler keeps reading and decoding up to 500 blocks after the client has gone, nothing limits how many such scans run at once, every historical read serialises on one store mutex, and the endpoint sits outside the per-source rate limiter that protects `/tx`. On a LAN-exposed node this is a cheap disk and CPU denial of service.

Counts: **Critical 0, High 0, Medium 1, Low 12, Info 12.**

## 2. The Medium

### R-1 · Medium · `/history` scans are not cancellable, not concurrency-bounded, and outside the rate limiter

**Where.** `internal/rpc/wallet.go` `scanHistory` loops from the head down calling `Chain.BlockAt` per height and decoding each block; `handleHistory` passes no context into it and nothing checks `r.Context()`. `handleExplorer` in `internal/rpc/web.go` runs the same scan for its 20-block window. `Server.txLimiter` is consulted only in `handleTx`. `store.Read` serialises every historical read behind `Store.readMu`.

**What that costs.** Per request, up to 500 reads of up to 1 MiB each and 500 `DecodeBlock` calls of up to 10,000 transactions each. `http.Server.WriteTimeout` arms a connection deadline; it does not stop the handler goroutine, and `net/http` caps neither connections nor handlers. A client that opens N requests for the maximum window and drops them queues N × 500 reads on the one mutex. The server-side bounds are correct and pinned (`TestHistoryWindowIsBoundedAndSaysWhatItScanned`, `TestHistoryBlocksClampsTheScanAtTheMaximum`); they bound one request, not the rate of requests.

**Scenario.** The node is started with the documented `--http 0.0.0.0` on a Pi. A host on the LAN loops `GET /history?address=…&blocks=500` and aborts each after the first byte. The disk and one core are saturated indefinitely, and `Append` waits behind in-flight readers (R-2 below). On the devnet, block size can be inflated first with faucet-funded transfers.

**Fix.** Pass `r.Context()` into `scanHistory` and return on `ctx.Err()` each iteration. Add a small package-level semaphore around the scanning handlers (four is plenty) returning 503 when full. Charge `/history` to the per-source bucket, weighted by the window requested. Pin with a test that cancels the request mid-scan and asserts the loop stops.

## 3. Low findings

### 3.1 Wallet CLI (`cmd/b10coin/wallet.go`, `main.go`)

- **W-1 · Low** `claim --key` checks only `chain_id` against the compiled-in devnet and then signs with the node-reported genesis hash, while the ephemeral `claim` signs with the compiled-in hash; `connectWalletNode` accepts any 32-byte hash; `builtTx.print` never shows the chain ID. A node reporting the devnet chain ID with another chain's hash obtains a claim or transfer valid on that other chain. Refuse `t.genesis != g.Hash()` in `claimWithKey`; print `chain` in the preview; consider a `--genesis-hash` pin.
- **W-2 · Low** `cmdHistory` prints `e.Type`, `e.From` and `e.To` from the node unparsed, and `cmdBalance` prints `ChainID` with `%s`. A hostile node can fabricate rows with embedded newlines or erase the truncation notice with terminal escapes. Parse `From` and `To` through `types.ParseAddress`, map `Type` through the closed label set, quote anything else.
- **W-3 · Low** `cmdHistory` checks the address echo only when the node sends one, and the server marks `historyResponse.Address` as `omitempty`; `readAccount` refuses a missing echo. Require the echo whenever the request was filtered.
- **W-4 · Low** `cmdSend` loads the key file twice, once for the self-transfer check and again inside `connectWalletNode`. Load once and pass the key through.
- **W-5 · Low** `historyBlocksHelp` promises the node clamps anything above 500, but `historyBlocks` parses with a 31-bit limit, so a larger value is a 400. Clamp or refuse at the client and say which.
- **W-6 · Low** The ephemeral `claim` still prints the private key to stdout by default (`--print-key` defaults to true). The previous justification, that it was the only way to the coins, is gone now that `claim --key` is the shipped path and the walkthrough uses it. Flip the default.

### 3.2 RPC, explorer and faucet page (`internal/rpc`)

- **R-2 · Low** `Chain.BlockAt` holds the chain read lock across the store read and the decode; `/history` multiplies that by 500. Go's writer-preferring lock means one scan cannot starve `Append`, but every reader already inside a serialised disk read delays it. Pre-existing for `/block`; `/history` raises the frequency. Copy the head under the lock, release it, then read from the store.
- **R-3 · Low** The faucet page's secret guard, `keyShape`, matches only an exact 64- or 128-character bare hex string. A pasted key file (browsers strip newlines), a `0x`-prefixed key or one with a trailing space fails `ParseAddress` and is echoed by `queryEcho` into the page, up to 64 bytes, which for the JSON file is about 15 bytes of the seed. The value is already in the URL because the form is GET, but the page's own text promises no secret reaches the body. Trim and refuse any run of 64 or more hex digits, or stop echoing the input at all.
- **R-4 · Low** `explorerView` reads its window twice: `recentBlocks` for the block table and `scanHistory` for the transaction list. Roughly 40 reads and decodes where 20 would do, on an unlimited endpoint. Let one pass feed both tables.

### 3.3 Tests and documentation

- **T-1 · Low** `TestHistoryIsSafeDuringAppends` (`internal/rpc/server_test.go`) `continue`s on every HTTP and decode error and never counts successes, so a `/history` that always returns 500 passes it. The explorer and faucet variants fail on any error; make this one match.
- **T-2 · Low** `faucetNodeURL` and `dnsName` (`internal/rpc/web.go`) sanitise the `Host` header before it is rendered into the `b10coin claim --node …` line users paste into a shell. By reading they are sound: fixed scheme, numeric port, host must parse as an IP or match letters, digits, dot and dash. No test references them. Add hostile `Host` cases.
- **D-1 · Low** README's architecture row for `cmd/b10coin` still lists `devnet, node, keygen, claim, stake, unstake, withdraw, version, help` and omits `balance`, `history` and `send`, which `main()` dispatches. The rewrite in `9da8bf4` missed this row. The transport row's A-2 wording from `5dbe3f4` was not reverted.

## 4. Informational

- **W-7** `balance` and `history` present the node's word with no state-root or signature check; `history`'s printed caveat is about window completeness, not authenticity, and the README says it for `history` only. One line in each verb's output would close it.
- **W-8** `walletAddress` loads the private half just to derive an address the key file already records in clear; a public-only loader would keep secrets out of read verbs.
- **W-9** `cmdBalance` requires a 32-byte genesis hash it never uses, and prints a height read in a different request from the balance.
- **W-10** Plain `http://` is the default with no warning for a non-loopback `--node`; the key never leaves the host, the preview surfaces tampered replies, and HTTPS works through the default transport. `keystore.Load` cannot be pointed at a non-key file usefully: it requires versioned JSON with matching halves and reports only path and lengths.
- **R-5** No `frame-ancestors` in the CSP and no `X-Frame-Options`; both pages are GET-only with no state change, so framing is harmless today.
- **R-6** `/history` answers 405 without an `Allow` header, consistent with the older endpoints; `HEAD` is refused on all three new routes.
- **R-7** `faucet.html` says the page is "bound to the node's loopback address"; that is the `--http` default, not a property of the handler, and the README documents `--http 0.0.0.0`.
- **R-8** `scripts/acceptance-walkthrough.sh` never fetches `/faucet`, `/explorer` or `/history`; the pages rest on unit tests only, while the walkthrough presents them as the milestone's deliverables.
- **R-9** On a chain shorter than 20 blocks the explorer rebuilds the genesis block, including its state and Merkle root, on every request through `BlockAt(0)`.
- **T-3** `explorer.html` hard-codes "20" in prose while the limits list interpolates `explorerBlocks` and `explorerTxs`; change one constant and the prose lies.
- **T-4** `scripts/check-plan.sh` is not run in CI and prints `PLAN PARITY OK`, not the plan's promised `PLAN OK`. The README's acceptance root `98e5cf46…` is still asserted nowhere; CI checks the exit code only.
- **P-1** M6 landed as eight direct pushes to `m6` with no pull request. `main` has no branch protection. The nine process gaps from the previous reports are unchanged: no coverage in CI, no fuzz job or corpora, `t.Skip` in `TestARebuiltDriverDoesNotBurnRoundZeroOnARunningClock`, eight ignored `Open` errors in `store_test.go`, `Sscanf` stall parsing in the simnet tests, no build tag on the subprocess CLI tests, no `CONTRIBUTING.md`, no `CODEOWNERS`, no signing step in the release job.

## 5. Test coverage

**What M6 pins, and pins well.** On the CLI: field-exact transfers signed against the reported hash (`TestSendVerbSubmitsATransferWithTheRightFields`), printed bytes equal to posted bytes minus the signature (`TestSendPostsExactlyThePrintedBytesPlusASignature`), hostile fee refused before signing without echoing it into the hint (`TestSendRefusesAHostileFee`), cover checks, zero amount, self-transfer and bad address refused before any network read, dry-run posting nothing, integer amount parsing, `claim --key` signing for the file's key with the account's nonce and writing no file, stable `balance` output, the history window and its limit, refusal of another account's reply. On the server: both parties see a transfer, window clamp and 200-entry cap, garbage windows and methods refused, an unreadable block masked as a generic 500 with no path and no partial table, the explorer unable to widen its scan, both pages escaping an injected `"><script>` through `?address`, no script or external resource in either page, the faucet page unable to solve, sign or submit (asserted on the source tree), the explorer sharing the node's one listener, all three endpoints under concurrent appends with the race detector on. The walkthrough script asserts output lines, not exit codes, and is shellcheck-clean at the CI severity. No new test sleeps, uses a wall-clock margin, skips, logs instead of asserting, or builds a subprocess.

**Missing, concretely.**
1. A `/history` request cancelled mid-scan stops the loop; N concurrent scans are bounded (R-1).
2. `/history` under a deleted segment returns the generic error with no path (the explorer has this test; `/history` does not).
3. `blocks` values at and above the 31-bit limit return 400; `history --blocks 501` and above at the CLI.
4. Hostile `Host` headers on `/faucet` (`a;$(id)`, `a@b:80`, `[::1]:8645`, `x:99999`) yield the default or the exactly validated `--node` line (T-2).
5. Partial-secret echo variants on the faucet page: the JSON key file, `0x`-prefixed, padded (R-3).
6. A genesis `ChainID` containing `<script>` rendered on both pages.
7. `TestHistoryIsSafeDuringAppends` counting successful reads (T-1).
8. `send` with amount plus fee overflowing; `send --max-fee` raising and holding the ceiling; non-TTY `send` without `--yes`; `--yes --dry-run` precedence on the transfer path.
9. A verb refusing a `--key` that is a directory, a 0644 file, or a non-key file before any network read.
10. `claim --key` against a node reporting the devnet chain ID with a foreign genesis hash (W-1); a `/history` reply with `address` omitted, unparseable `From`/`To`, or a `Type` containing a newline (W-2, W-3).
11. `/explorer` counting its `BlockAt` calls (R-4).

## Appendix: verified-sound properties

- No consensus, state or type file changed: the diff touches `cmd/b10coin`, `internal/rpc`, scripts, CI and docs only.
- Pages: `html/template` parsed once from `templateFS` at init (`pageTemplates`); `pageHeader` sets `nosniff`, `default-src 'none'; style-src 'unsafe-inline'`, `Cache-Control: no-store`; no `template.HTML`, no script, no `src` or `href`, pinned by `TestTheFaucetPageCannotSolveSignOrSubmit` and `TestTheExplorerPageHasNoScriptAndNoExternalResource`; both GET-only with `Allow: GET` on 405; rendered into a buffer before writing; store errors masked to a generic 500.
- `faucetView` reads one `AdmissionHead` snapshot and then the immutable published state; `explorerView` reads one `HeadSnapshot`; `handleHistory` reads `Height` once; no handler holds a chain lock across encoding or template execution; `faucetNodeURL` fixes the scheme, requires a numeric port and an IP or strict DNS-character host, else `defaultNodeURL`.
- Server-side bounds independent of client input: `historyBlocks` clamp to `maxHistoryBlocks`, `historyWindow` clamp to the head, `maxHistoryEntries`, `explorerBlocks` and `explorerTxs` constants; `ParseUint` at 31 bits refuses negative, fractional and overflowing windows; the scan loop terminates at `from` without unsigned underflow.
- One scan implementation for the wallet and the explorer: `scanHistory`.
- Wallet signing: `crypto.Sign` is reached only through `walletTarget.submit` (and the unchanged ephemeral `cmdClaim`); `buildTx` encodes once and decodes once so what is printed is what is signed; order is print, ceiling on the decoded fee, dry-run, confirmation, sign, post; `defaultMaxFeeSparks` is 1 and `claimWithKey` passes a ceiling of 0 so any fee on a claim is refused; recipient and amount come only from `--to` through `types.ParseAddress` and `--amount` through `genesis.ParseB10`; self-transfer, zero amount and a zero reported minimum fee are refused before signing.
- Confirmation: `confirmTransaction` through `askConfirmation` and `stdinIsTerminal`; EOF, an empty line and a non-terminal stdin are refusals; `--dry-run` returns before confirmation.
- Keys: `keystore.Load` only; no private key byte formatted, logged or written on any `--key` path (`TestClaimWithKeyGoesThroughTheEnvelope` pins no file written); `cmdKeygen` and `builtTx.print` print public keys only.
- Client bounds: `claimHTTP` 15-second timeout, `CheckRedirect` refuses every redirect, every body read through a 1 MiB `LimitReader`; `connectWalletNode` and `readAccount` refuse an `/account` echo for another address.
- Money rendering through `genesis.FormatB10` integer arithmetic throughout; uint64 amounts travel as JSON numbers and every committed amount is below 2^53 by the supply cap.
- Walkthrough script: `set -u -o pipefail`, `unset CDPATH IFS`, `mktemp` work directory, an `EXIT` trap that terminates the node by a numerically validated PID, waits for the port to close and removes the directory; arguments validated, no `eval`, no `curl` or `jq`; the one executable fence is extracted by info string and must be unique; assertions on printed lines including the queued-before-paid ordering and the exact final balances.
- CI: the walkthrough step runs in the `test` job after the four devnet commands; eight green runs on the branch.
