# M2: The Faucet — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make b10coin's coins exist and be claimable — a protocol-controlled faucet that emits on a fixed schedule and pays out only against an Argon2id proof-of-work puzzle, one claim per key per epoch.

**Architecture:** Two new concepts, both small. First, an emission rule: every block credits a fixed, halving reward to a **faucet address that has no private key**, so the coins are minted but unspendable except through the claim rule. Second, a claim rule: a `TxFaucetClaim` proves it burned a few seconds of CPU on an Argon2id puzzle bound to the claimant's key and the current epoch, and in exchange the state machine debits the faucet and credits the claimant — once per key per epoch.

**Tech Stack:** Go 1.23+, `golang.org/x/crypto/argon2` (the second direct dependency — see Decision 1), standard-library `testing`.

**Spec:** `docs/2026-10-02-b10coin-design.md` — §6.4 (issuance) is the authority for this milestone; §6.2 (transaction types) defines the claim's shape; §9 defines how it must be verified.

**Prerequisite milestone:** M0–M1 is complete on branch `m0-m1-foundation`, with `go run ./cmd/b10coin devnet --blocks 100` printing `OK`.

## Global Constraints

- **Module path:** `github.com/cti97/b10coincom`
- **Go floor:** `go 1.23`
- **Dependencies:** TWO direct external modules: `lukechampine.com/blake3` (M0–M1) and `golang.org/x/crypto` (pinned `v0.41.0`, for `argon2`). See Decision 1. Their transitive requirements (`cpuid/v2`, `x/sys`) are recorded `// indirect` and are not chosen dependencies. No others — no CLI framework, no logging framework, no test framework, no database.
- **Go floor stays `go 1.23`.** CI is pinned to Go 1.23, so a dependency that demands a newer toolchain must be pinned back, not allowed to raise the floor.
- **Base unit is `spark`;** `1 b10 = 10^8 sparks`. All monetary values are `uint64` sparks. Never use floats for money.
- **Canonical encoding only.** Every consensus structure is encoded with the M0–M1 helpers in `internal/types/codec.go`. Never `encoding/gob`, never JSON, never iterate a Go map when producing bytes that get hashed.
- **Determinism is the invariant that matters most.** Two nodes with the same state and the same block must reach byte-identical state roots. Any map iteration that reaches a hash is a fork.
- **PoW here is not consensus.** It is a rate limiter on the faucet. Do not let it leak into block production, validation, or the validator set.
- **Import direction.** `internal/faucet` imports only the standard library and `golang.org/x/crypto`. `internal/state` and `internal/genesis` both import `internal/faucet` (for the puzzle parameters), and `internal/chain` imports `internal/faucet` (for `Reward`). Nothing imports `internal/faucet` from below it, and `internal/state` must still NOT import `internal/genesis` — that is why `State` takes its faucet parameters as fields set at construction rather than reading genesis itself.
- **The faucet address has no private key.** No code path may ever require, accept, or check a signature from it.
- **Never mint more than the cap.** The realized emission must never exceed `TotalSupplySparks`.
- **No secrets in the repo.** Devnet keys are documented public fixtures.
- **Every task ends with `go test -count=1 ./...` green and a commit.** Use `-count=1`: Go's result cache once reported a flaky test green in this project.

## Design decisions

These are the consequential calls. Each is forced by the spec or by the arithmetic; none is arbitrary, and each is recorded so a later reader does not have to re-derive it.

**1. Add `golang.org/x/crypto` for Argon2id.** The spec mandates Argon2id (§6.4). Go's standard library has no Argon2 implementation, and hand-rolling a memory-hard KDF would be reckless. This makes two direct dependencies; the M0–M1 "exactly one direct module" constraint is amended, not broken by accident.

**2. `state.Account` gains `ClaimedEpoch uint64`.** The claim's rate limit must be committed state or it is not consensus. The account leaf encoding becomes `U64(Balance) || U64(Nonce) || U64(ClaimedEpoch)`, so **every state root changes**. That is expected and unavoidable — new state must be committed. Consequence: the M0–M1 golden vectors in `internal/state/apply_test.go` are superseded and MUST be re-derived and re-pinned as part of Task 3, with the old and new values recorded in the test's comment so the change is visible. The "do not re-capture" rule still holds for every *other* reason.

**3. Emission is credited BEFORE the block's transactions, for heights `h >= 0`.** For a block at height `h` the transition is: (a) credit `Reward(h)` to the faucet, (b) apply the block's transactions in order. `Build`, `Append` and replay must all do exactly this, or state roots diverge. Crediting first means a claim in block `h` may spend the emission from block `h`.

**4. `Reward(h) = InitialRewardSparks >> (h / HalvingIntervalBlocks)`, with NO special case for height 0.** Height 0 is the genesis mint the spec names ("the genesis block mints to a faucet account"). Because interval 0 spans heights `0..HALV-1`, the genesis mint falls out of the same formula. Reward reaches 0 at halving 26 (height 546,000,000, ≈34.6 years at 2 s blocks).

**5. The realized emission is 2.52 b10 BELOW the cap, and can never exceed it.** The spec's identity `R0 × HALVING × 2 == TotalSupply` is a *parameter consistency* check on the idealized total; integer truncation in the shifts means the realized sum is
`HALVING × Σ(R0 >> k) = 2,099,999,748,000,000 sparks = 20,999,997.48 b10`,
i.e. **252,000,000 sparks (2.52 b10) short** of the 21,000,000 b10 cap. The unissued remainder is never minted. A test must pin that the realized total is `<=` the cap. Omitting the genesis mint would make the shortfall 3.02 b10 instead of 2.52.

**6. A `FaucetClaim` uses and bumps the account nonce, like any other transaction,** AND is rate-limited by the epoch marker. The spec's field list for the type is abbreviated (it lists no nonce, yet every transaction carries one), so this is consistent with it. Layering both protections costs nothing and keeps the state machine uniform.

**7. The puzzle is `Argon2id(pubkey || U64(epoch) || U64(pow_nonce))` under salt `"b10coin-faucet-pow"`,** valid when the 32-byte digest, read big-endian, is strictly below a 32-byte `target`. Binding the public key and the epoch into the digest means a solution found for one key or one epoch is useless for another, so solutions cannot be traded or replayed.

**8. Devnet uses trivial Argon2 parameters and an easy target; testnet uses the spec's ≈3 s ones.** A 3 s puzzle would make the test suite unusable. The Argon2 parameters and the target are genesis parameters, so both configurations are legitimate. Devnet: memory 64 KiB, 1 iteration, 1 lane, and a target requiring a handful of attempts. Testnet: the spec's ≈3 s tuning, recorded in `genesis/testnet.json`.

**9. Epochs are 1-BASED: `epoch(h) = h / EpochBlocks + 1`.** This is not cosmetic. An account that has never claimed holds `ClaimedEpoch == 0`, so under 0-based epochs a fresh account is refused in epoch 0 (the rule reads `0 >= 0`), and **no claim can succeed before the first epoch boundary** — the devnet's first claim, at height ~2, would always fail. Epochs therefore start at 1.

A claim is valid only when **`tx.Epoch == epoch(currentHeight)`** — so the puzzle is bound to a time window and a solution pre-computed for a later epoch cannot be spent early — **and** `account.ClaimedEpoch < tx.Epoch`. On success `ClaimedEpoch` becomes `tx.Epoch`.

**9a. `State` carries the current height as EXECUTION CONTEXT, never as committed state.** The claim rule needs the height to derive the epoch, but `ApplyTx(tx)` takes no height. So `State` gains an unexported `height` field and a setter the chain calls before applying a block's transactions. It is deliberately NOT hashed into the state root: the block header already commits to the height, and the claim rule is the only thing that needs it. `Clone` must carry it.

**10. The faucet is an ordinary account with no key.** It is created by `chain.genesisState` at the address `genesis.FaucetAddress()`, with a zero balance (so it is pruned until emission funds it). `applyFaucetClaim` debits it **as a protocol rule, without any signature** — it has no key, so no signature can exist. This is the whole point of the design and the one place where an account is modified without its owner's signature.

package faucet

import (

// fastParams are deliberately trivial so the suite stays quick. The testnet
// parameters are the spec's ~3s ones; a 3s puzzle would make this file unusable.
var fastParams = Argon2Params{MemoryKiB: 64, Iterations: 1, Parallelism: 1}

// easyTarget is every bit set except the top one, so roughly half of all
// digests satisfy it and a solve takes a couple of attempts.
func easyTarget() [32]byte {
	var t [32]byte
	for i := range t {
		t[i] = 0xFF
	}
	t[0] = 0x7F
	return t
}

func TestPowDigestIsDeterministic(t *testing.T) {
	pub := []byte("a-32-byte-public-key-padded-here!")
	a := PowDigest(pub, 7, 42, fastParams)
	b := PowDigest(pub, 7, 42, fastParams)
	if a != b {
		t.Fatal("PowDigest is not deterministic")
	}
}

// The puzzle must bind the key AND the epoch: a solution for one is worthless
// for another, which is what stops solutions being traded or replayed.
func TestPowDigestIsBoundToKeyAndEpoch(t *testing.T) {
	pub := []byte("a-32-byte-public-key-padded-here!")
	other := []byte("a-different-public-key-padded-000!")
	base := PowDigest(pub, 7, 42, fastParams)

	if base == PowDigest(other, 7, 42, fastParams) {
		t.Fatal("digest ignored the public key")
	}
	if base == PowDigest(pub, 8, 42, fastParams) {
		t.Fatal("digest ignored the epoch")
	}
	if base == PowDigest(pub, 7, 43, fastParams) {
		t.Fatal("digest ignored the nonce")
	}
}

func TestMeetsTarget(t *testing.T) {
	var zero, big [32]byte
	for i := range big {
		big[i] = 0xFF
	}
	if !MeetsTarget(zero, big) {
		t.Fatal("the smallest digest must meet the largest target")
	}
	if MeetsTarget(big, big) {
		t.Fatal("the comparison must be STRICTLY below the target")
	}
	if MeetsTarget(big, zero) {
		t.Fatal("the largest digest must not meet a zero target")
	}
}

// A target of zero is unsatisfiable, so Solve must exhaust its attempts and
// report failure rather than looping forever.
func TestSolveGivesUpWhenUnsatisfiable(t *testing.T) {
	pub := []byte("a-32-byte-public-key-padded-here!")
	var impossible [32]byte
	if n, ok := Solve(pub, 1, impossible, fastParams, 4); ok {
		t.Fatalf("Solve succeeded against an impossible target with nonce %d", n)
	}
}

// The round trip that matters: what Solve finds, verification accepts.
func TestSolveThenVerify(t *testing.T) {
	pub := []byte("a-32-byte-public-key-padded-here!")
	target := easyTarget()
	nonce, ok := Solve(pub, 3, target, fastParams, 1_000)
	if !ok {
		t.Fatal("Solve failed to find a solution it should have found")
	}
	if !MeetsTarget(PowDigest(pub, 3, nonce, fastParams), target) {
		t.Fatalf("the nonce Solve returned (%d) does not verify", nonce)

// Package faucet implements b10coin's issuance faucet: the proof-of-work puzzle
// that rate-limits claims, and the emission schedule that funds them.
//
// PoW here is NOT consensus. It is a rate limiter on a faucet. The difficulty is
// calibrated so a Raspberry Pi completes a puzzle in seconds, and at that
// difficulty ASICs confer no meaningful advantage. The chain's security comes
// from the validator set (M3), not from this.
package faucet

import (
	"encoding/binary"
	"math/big"

	"golang.org/x/crypto/argon2"
)

// powSalt domain-separates the faucet puzzle from any other use of Argon2id.
var powSalt = []byte("b10coin-faucet-pow")

// Argon2Params configures the puzzle. Argon2id is memory-hard, so the cost of a
// guess is dominated by memory bandwidth rather than raw compute — which is
// exactly why ASICs do not help at this difficulty.
type Argon2Params struct {
	MemoryKiB   uint32
	Iterations  uint32
	Parallelism uint8
}

// PowDigest computes the puzzle digest for a claimant key, an epoch and a nonce.
//
// The claimant's public key and the epoch are both inside the hashed preimage,
// so a solution is worthless for any other key or any other epoch: solutions
// cannot be traded between claimants or replayed in a later epoch.
func PowDigest(pubkey []byte, epoch, nonce uint64, p Argon2Params) [32]byte {
	pre := make([]byte, 0, len(pubkey)+16)
	pre = append(pre, pubkey...)
	var b [8]byte
	binary.BigEndian.PutUint64(b[:], epoch)
	pre = append(pre, b[:]...)
	binary.BigEndian.PutUint64(b[:], nonce)
	pre = append(pre, b[:]...)

	out := argon2.IDKey(pre, powSalt, p.Iterations, p.MemoryKiB, p.Parallelism, 32)
	var d [32]byte
	copy(d[:], out)
	return d
}

// MeetsTarget reports whether digest is STRICTLY below target, both read as
// big-endian 256-bit unsigned integers. A smaller target is a harder puzzle.
func MeetsTarget(digest, target [32]byte) bool {
	return new(big.Int).SetBytes(digest[:]).Cmp(new(big.Int).SetBytes(target[:])) < 0
}

// Solve searches nonces from 0 upward for one whose digest meets target, giving
// up after maxAttempts. The upward scan is deterministic and therefore testable;
// a real claimant should start from a random nonce, which is strictly better but
// is not required for correctness.
func Solve(pubkey []byte, epoch uint64, target [32]byte, p Argon2Params, maxAttempts uint64) (uint64, bool) {
	for n := uint64(0); n < maxAttempts; n++ {
		if MeetsTarget(PowDigest(pubkey, epoch, n, p), target) {
			return n, true
		}
	}
	return 0, false
}
```

package faucet

// Emission schedule.
//
// The reward is paid into the protocol-controlled faucet account, which has no
// private key; coins leave it only through the claim rule in the state machine.
//
// Reward is NOT special-cased at height 0. Interval 0 spans heights
// 0..HalvingInterval-1, so the genesis mint the spec calls for falls out of the
// same formula.
//
// The realized series is slightly SHORT of the supply cap because each halving
// truncates: for the specified parameters it totals 2,099,999,748,000,000 sparks
// (20,999,997.48 b10), 252,000,000 sparks (2.52 b10) below the 21,000,000 b10 cap.
// Those sparks are simply never minted. The cap is a maximum, never a target, and
// the series can never overshoot it. Omitting the genesis mint would widen the
// shortfall to 3.02 b10, which is why height 0 is included.
func Reward(height, initialReward, halvingInterval uint64) uint64 {
	if halvingInterval == 0 {
		return 0
	}
	halvings := height / halvingInterval
	if halvings >= 64 {
		return 0
	}
	return initialReward >> halvings
}

// SeriesTotal is the sum of Reward over every height from 0 to the point the
// reward reaches zero. It is used by tests and by the genesis-parameter check to
// prove the schedule cannot exceed the cap.
func SeriesTotal(initialReward, halvingInterval uint64) uint64 {
	if halvingInterval == 0 {
		return 0
	}
	var halved uint64
	for k := uint64(0); k < 64; k++ {
		r := initialReward >> k
		if r == 0 {
			break
		}
		halved += r
	}
	// Each halving interval spans exactly halvingInterval heights, and interval 0
	// starts at height 0, so the whole series is halvingInterval * sum of halvings.
	if halved > ^uint64(0)/halvingInterval {
		return ^uint64(0) // saturate rather than wrap; a wrapped total could pass a cap check
	}
	return halved * halvingInterval
}
```

func (s *State) Root() [32]byte {

	st := state.NewWithParams(state.Params{
		FaucetAddress: g.FaucetAddress(),
		ClaimAmount:   g.Params.ClaimAmountSparks,
		EpochBlocks:   g.Params.EpochBlocks,
		PowArgon2:     g.Params.FaucetPowArgon2,
		PowTarget:     g.Params.FaucetPowTarget,
	})
	for _, d := range g.DevAccounts {
		addr := types.AddressFromPub(d.PubKey)
		acc := st.Get(addr)
		acc.Balance += d.BalanceSparks
		st.Set(addr, acc)
	}
	// The genesis mint the spec names. Reward is not special-cased at height 0,
	// so this is the same formula every later block uses.
	if r := faucet.Reward(0, g.Params.InitialRewardSparks, g.Params.HalvingIntervalBlocks); r > 0 {
		acc := st.Get(g.FaucetAddress())
		acc.Balance += r
		st.Set(g.FaucetAddress(), acc)
	}
	return st
}

// claim is solved and signed just as carefully as the first, so only the epoch
// marker can reject it.
func TestDevnetRefusesASecondClaimInTheSameEpoch(t *testing.T) {
	dir := t.TempDir()
	g := genesis.Devnet()
	c, err := chain.Open(g, dir)
	if err != nil {
		t.Fatal(err)

	_, priv := genesis.DevValidatorKey()
	mp := mempool.New(100)

	pub, key, err := crypto.GenerateKey()
	if err != nil {
		t.Fatal(err)
	}
	params := state.Params{
		FaucetAddress: g.FaucetAddress(),
		ClaimAmount:   g.Params.ClaimAmountSparks,
		EpochBlocks:   g.Params.EpochBlocks,
		PowArgon2:     g.Params.FaucetPowArgon2,
		PowTarget:     g.Params.FaucetPowTarget,

	// Block 1 funds the faucet with its emission, so a claim can be paid.

			Nonce: nonce, Epoch: epoch, PowNonce: pow,

		sigHash := tx.SigningHash()
		tx.Sig = crypto.Sign(key, sigHash[:])

	}

## Self-Review

**Spec coverage.** §6.4's table maps as follows: base unit and cap — carried from M0–M1, pinned by `TestSupplyCapIsPinned`; initial reward, halving interval and the 21,000,000 emission endpoint — Task 2; `CLAIM_AMOUNT` — Task 5; the Argon2id puzzle — Task 1, tuned per chain in Task 6; one claim per key per epoch — Tasks 3 and 5; the funding invariant ("a claim is valid only if the faucet balance covers it") — Task 5; the demotion of PoW to a rate limiter — structural, and asserted by the absence of any PoW in `chain`/`node`/consensus. §6.2's `FaucetClaim` row — Task 4. §9's "one command proves it works" — Task 8.

**Not in this plan, deliberately:** the other three transaction types (`Bond`, `Unbond`, `Withdraw` — M5); the fee market (after emission ends, which is ~34.6 years away); a key file or keystore; any wallet UX beyond the single `claim` command.

**The two things most likely to go wrong, and where they are guarded.** First, emission applied in one code path but not another — guarded by a single helper called from all three of `Build`, `Append` and replay, plus `TestReplayReproducesEmission`. Second, the state-root change being absorbed silently — guarded by re-pinning both golden vectors with their superseded values written down, and by proving the new vectors move under both a domain-label change and a zeroed `ClaimedEpoch`.

**Honest limits.** The testnet Argon2 tuning is asserted from the spec, not measured on real hardware; it must be re-tuned before any public testnet opens, and the plan says so where the value is set. The puzzle's difficulty is likewise a guess at what makes a Pi wait seconds rather than minutes. And the faucet's anti-farming property is only as good as the one-claim-per-key-per-epoch rule — a determined attacker with many keys is rate-limited, not prevented, which is the trade the spec accepted when it chose a faucet over a premine.
